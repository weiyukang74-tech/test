# 病程记录关键词筛选设计

## 1. 目标

在不改变证据标签路由权的前提下，减少送入复核 Agent 的病程记录数量。

当某个具体证据标签通过标签映射表路由到病程记录时，查询规划 Agent 为该证据项生成高召回检索词根。查询程序使用这些词根筛选病程记录：有命中时只保留命中的完整文书；没有命中时回退到原本应查询的全部病程记录，确保首版不会因关键词遗漏而丢失证据。

首要验收目标是关键证据零漏失，Token 降幅是第二目标。

## 2. 非目标

- 本期不允许查询规划 Agent 越过证据标签，主动增加新的病程数据源。
- 本期不修订证据标签体系或标签映射表。
- 本期不让正则命中直接代表证据成立。
- 本期不在过滤阶段判断阳性、阴性、否定、家族史或患者归属。
- 本期不对所有 `DS-M-*` 医疗文书做关键词过滤。
- 本期不继续以公共部分提取作为默认病程压缩方案。

## 3. 当前职责与改造后职责

### 3.1 当前职责

- 规则证据 Agent 生成申诉命题、证据标签和 `target_fact`。
- 标签映射表将具体证据标签映射到诊断、医嘱、费用、病程等数据源。
- 查询程序按标签映射查询数据源。
- 查询规划 Agent 目前只为费用和手术操作类证据项生成费用明细关键词，查询来源固定为 `DS-S-002 费用明细`。
- 复核上下文构建阶段目前会对医疗文书执行公共部分提取。

### 3.2 改造后职责

- 规则证据 Agent：继续只负责“需要证明什么”，输出命题、标签和 `target_fact`。
- 标签映射：继续拥有绝对路由权，决定“是否查询病程、查询哪些病程来源”。
- 查询规划 Agent：对已经由标签映射到病程记录的具体证据项生成“如何筛选”的检索词根。
- 查询程序：把模型词根编译成安全匹配规则，筛选病程并执行无命中回退。
- 复核 Agent：阅读被召回的完整病程原文，判断证据是否成立。

## 4. 数据流

1. 规则证据 Agent 产出 `P01、P02、P03...` 以及每个命题下的具体证据标签。
2. 查询规划前先读取标签映射结果。
3. 只有来源包含病程记录的具体证据标签进入病程关键词规划。
4. 查询规划 Agent 针对每个具体证据标签独立生成 1 至 5 个高召回词根。
5. 查询程序先按原有标签路由查询病程记录。
6. 查询程序对 `recordType=病程记录` 的文书执行关键词匹配。
7. 不同证据点、不同标签和不同词根之间采用 OR 召回。
8. 任意词根命中时，保留该篇文书的完整 `recordContent`。
9. 同一篇文书命中多个证据项时只保留一份，并记录所有命中来源。
10. 如果所有候选病程均未命中，回退到过滤前的全部候选病程。
11. 被选中的病程以完整原文进入复核上下文，不再拆成 `common_content` 和 `unique_content`。

## 5. 路由规则

### 5.1 标签为硬开关

只有具体证据标签的映射来源中存在病程记录时，才允许生成和执行 `record_search_terms`。

没有映射到病程记录的证据项：

- 不生成病程检索词；
- 不参与病程筛选；
- 不得因为命题文本中出现医学概念而补查病程。

### 5.2 过滤范围

本期仅过滤 `recordType=病程记录` 的高数量文书。

入院记录、出院记录、手术记录、护理记录、病案首页等其他文书保持现有查询和返回逻辑，即使它们的来源代码同样以 `DS-M-*` 开头，也不进入本期关键词过滤。

### 5.3 后续扩展边界

未来可以为标签体系缺失增加模型补充路由，但必须满足：

- 与标签映射路由分开记录；
- 使用明确的 `plan_origin` 标记；
- 输出补充原因和置信信息；
- 可单独关闭和统计；
- 不在本期实现。

## 6. 查询规划输出

病程关键词计划绑定到“命题下的具体证据标签”，而不是只绑定到整个 `Pxx`。

建议在现有查询计划的 `plans` 数组中增加病程计划，结构如下：

```json
{
  "query_id": "QP-P03-02",
  "supports_facts": [
    {
      "proposition_id": "P03",
      "一级证据域": "病理",
      "二级证据标签": "病理结果",
      "target_fact": "确认患者雌激素受体状态",
      "necessity": "REQUIRED"
    }
  ],
  "source": "DS-M-IP-004 日常病程记录",
  "query_type": "MEDICAL_RECORD_KEYWORD_FILTER",
  "plan_origin": "TAG_MAPPED",
  "record_search_terms": ["雌激素", "ER"]
}
```

约束：

- 每个病程证据项独立生成计划。
- `record_search_terms` 为非空字符串数组，去重后最多 5 个。
- 模型只输出词根，不输出正则表达式。
- 关键词可以是中文医学词根、英文缩写或稳定的常见名称。
- 禁止输出“患者、病历、是否、相关、本次、检查”等无区分度词语。
- 禁止把二级证据标签名称（如“治疗方案”）原样作为词根。标签名是分类名称而不是病历原文，容易命中无关文书并虚假满足必需证据覆盖；查询程序同样忽略这类词根。
- 禁止输出单个字、纯数字或单个英文字母（如“片”“28”“R”），这类词根会命中大量无关文书。
- 词根按医生在病程中的实际写法生成，而不是照抄收费项目名称或医保规则原文；治疗或操作类事实须包含所属治疗类别或执行科室的常见写法。
- 禁止把其他命题的概念混入当前证据项。

## 7. 模型输入与泛化规则

每次关键词生成只提供：

- 当前规则标识和规则原文，作为背景；
- 当前命题 `proposition_id` 和命题描述；
- 当前具体证据标签；
- 当前标签的 `target_fact`；
- 当前标签映射到的病程来源。

模型生成的是用于召回原文的宽泛词根，而不是证据结论。例如：

- “雌激素受体阳性”可生成 `雌激素`、`ER`，不要求只搜索完整短语 `ER阳性`。
- “既往使用他莫昔芬”可生成 `他莫昔芬`，但不能因为同属一条规则而加入 `依西美坦`。
- “疾病进展”可生成有把握的临床表达，但不能凭空扩展为具体转移部位或治疗药物。

关键词命中仅表示文书值得送审。`ER阴性`、`未见ER阳性表达` 等内容仍应被召回，由复核 Agent 判断证据方向。

### 7.1 命中不足时按病历原文补充词根

首轮词根完全按规则文字生成，写法可能与病历原文不一致。当某个病程证据点的词根在该患者候选病程里命中不超过1篇时，允许补充一轮“按原文改写”：

- 命中0篇或1篇都会触发；命中超过1篇的证据点不触发，首轮词根保留。
- 给模型的是候选病程的真实片段：按文书类型分配篇数（大类型分到更多片段）、类型内按时间均匀取（覆盖整段住院期间）、同一类型内轮流取文书的前/中/后段（避免只看到开头的查体和生命体征），总量约一万五千字符，不是全量原文。
- 模型只做改写和补充，检索目标仍是该证据点；补充词根必须能在候选病程中真实命中，否则由程序丢弃，同时丢弃证据标签名称、单个字和纯数字。
- 每个证据点最多补充3个词根，每条规则最多补充3个证据点；原词根与补充词根取并集，并集超过5个时按“有命中的补充词根、有命中的原词根、未命中的原词根”顺序保留，被舍弃的原词根记录在计划中。
- 模型在片段中找不到对应写法时返回空数组，不硬凑词；此时词根不变，查询程序按命中不足安全回退。
- 该轮结果记录在计划的 `record_search_retry` 字段中，包含触发原因（`NO_KEYWORD_MATCH` 或 `LOW_KEYWORD_COVERAGE`）、候选篇数与命中篇数、抽样篇数与字符数、原词根及各自命中数、补充词根及各自命中数、被丢弃和被替换的词根，便于核对模型是否跑偏。
- 预检或模型调用失败只跳过该轮，不影响正常规划和查询。该轮可用 `--no-record-feedback` 关闭。

## 8. 匹配规则

### 8.1 统一规范化

匹配程序负责：

- 英文字母大小写不敏感；
- 全角和半角基础符号兼容；
- 忽略词根两侧无语义的空白；
- 对模型输出做正则转义；
- 不执行模型提供的任何原始正则。

### 8.2 英文缩写边界

英文缩写使用字母边界控制，目标是：

- `ER+`、`ER阳性`、`ER（90%）` 可以命中 `ER`；
- `HER2` 不应因为内部包含 `ER` 而命中 `ER`；
- 匹配规则需要覆盖常见的加号、减号、括号、冒号、空格和百分比写法。

### 8.3 合并语义

- 同一证据项内的词根是 OR。
- 不同证据项之间也是 OR：任一证据项的词根都可以命中本规则按标签路由取回的全部候选病程，不限于该证据项自身映射的病程来源。
- 文书命中任意有效词根即被选中。
- 文书去重沿用现有医疗文书唯一标识；如果现有标识不足，则以来源、就诊号、文书名称、记录时间和内容摘要组成稳定键。

## 9. 回退与错误处理

### 9.1 无命中回退

如果病程关键词计划存在，但候选病程零命中：

- 返回过滤前的全部候选病程；
- 设置 `filter_fallback=true`；
- 设置 `fallback_reason="NO_KEYWORD_MATCH"`；
- 不把零命中解释为证据不存在。

### 9.2 规划缺失或无效

以下情况同样保持原有全量病程，不进行破坏性过滤：

- 查询规划文件不存在；
- 对应病程证据项没有关键词计划；
- `record_search_terms` 为空或校验失败；
- 所有关键词在规范化后无效；
- 关键词匹配过程异常。

对应原因必须写入筛选统计，不能静默丢弃病程。

规划缺失或无效时 `enabled=false`，复核上下文沿用旧版公共部分处理，确保旧查询规划文件兼容。

### 9.3 部分计划

同一规则有多个病程证据项时，只要存在未获得有效关键词计划的病程证据项，就不能确认过滤覆盖完整。首版采用保守策略：回退全量病程，并记录 `fallback_reason="INCOMPLETE_FILTER_PLAN"`。

当全部计划有效但任一 `REQUIRED` 证据计划零命中时，同样回退全量病程，并记录 `fallback_reason="INCOMPLETE_FILTER_COVERAGE"`。未命中的 `SUPPLEMENTARY` 计划不触发整条规则回退，但该证据项自身的候选病程全部保留（证据项级回退），计入命中统计并记录在 `supplementary_evidence_fallbacks`。

## 10. 复核上下文格式

复核上下文继续保留完整病程文书，至少包含：

- 原有文书标识、来源、名称、类型、时间和 `recordContent`；
- `matched_propositions`；
- `matched_evidence_tags`；
- `matched_terms`。

规则级增加筛选统计：

```json
{
  "medical_record_filter": {
    "enabled": true,
    "filter_applied": true,
    "candidate_document_count": 68,
    "selected_document_count": 6,
    "filter_fallback": false,
    "fallback_reason": null,
    "planned_evidence_count": 3,
    "matched_evidence_count": 3,
    "required_planned_evidence_count": 2,
    "required_matched_evidence_count": 2
  }
}
```

存在被忽略的词根或证据项级回退时，另外输出 `ignored_search_terms` 和 `supplementary_evidence_fallbacks`，为空时不输出。

病程筛选计划完整可用时，选中文书或安全回退的完整文书不再进入公共部分提取。计划缺失、无效或不完整时 `enabled=false`，公共部分实现继续处理旧数据。

## 11. 兼容性

- 现有费用查询计划结构和行为保持不变。
- 没有病程关键词计划的旧查询规划文件继续按原逻辑返回完整病程。
- 查询计划索引继续以 `proposition_id + 一级证据域 + 二级证据标签` 精确关联，防止把一个标签的关键词应用到另一个标签。
- 新字段均为增量字段，复核 Agent 在字段不存在时仍能读取旧版上下文。
- CLI 的 `--plan-only` 和完整链路运行方式保持可用。

## 12. 代表性验证规则

依西美坦示例在当前规则库中是 `RULE-056`。它作为首个语义验证规则，至少覆盖：

- `ER+` 能被词根 `ER` 召回；
- `HER2` 不会单独触发 `ER`；
- 中文“雌激素受体阳性”能被 `雌激素` 召回；
- `ER阴性` 仍会被召回；
- 他莫昔芬、绝经状态、疾病进展等词根只绑定各自证据标签；
- 多个证据项命中文书取并集并去重；
- 命中文书保留完整 `recordContent`；
- 零命中或计划不完整时回退全量病程。

除 `RULE-056` 外，再选取多条病程数量较多、证据类型不同的规则执行 A/B 验证。

## 13. 测试策略

### 13.1 查询规划单元测试

- 只有映射到病程记录的证据标签进入病程关键词规划。
- 非病程标签不生成 `record_search_terms`。
- 每个具体证据标签独立输出和校验。
- 关键词去空、去重并限制为最多 5 个。
- 模型遗漏任一病程证据项时规划校验失败或标记为不完整。
- 现有费用规划测试保持通过。

### 13.2 匹配器单元测试

- 中文词根匹配。
- 英文大小写匹配。
- `ER+`、`ER阳性`、`ER（90%）` 命中 `ER`。
- `HER2` 不命中 `ER`。
- 正则特殊字符被当作普通文本安全处理。
- 多证据项 OR 合并和文书去重。

### 13.3 查询程序集成测试

- 有命中时仅返回命中的完整病程。
- 无命中时回退全部候选病程。
- 计划缺失、无效和不完整时回退全部候选病程。
- 非病程类型文书不受过滤影响。
- 命中元数据和规则级筛选统计正确。
- 新流程不把选中病程转换为公共部分分组。

### 13.4 全链路验收

- 使用 `RULE-056` 检查关键词规划、病程召回和复核上下文。
- 对多条高病程量规则执行过滤前后 A/B。
- 人工确认过滤后仍包含所有已知关键病程。
- 统计候选文书数、选中文书数、回退率、上下文字符数和参考 Token 数。

## 14. 验收标准

- 已知关键病程零漏失。
- 无标签路由的证据点不会触发病程查询。
- 命中文书保持完整原文。
- 无命中、计划缺失、计划无效或计划不完整时均安全回退。
- `ER` 的缩写匹配不会因 `HER2` 产生明显误召回。
- 费用查询和其他非病程数据源行为无回归。
- 输出能够解释每篇病程为什么被选中。
- A/B 报告能够独立展示病程数量和上下文 Token 的变化。

## 15. 实施顺序

1. 扩展查询规划的数据选择、提示词、输出校验和计划结构。
2. 在查询程序中增加独立的病程词根匹配器。
3. 在按标签查询到病程后、构建复核上下文前执行筛选与回退。
4. 扩展复核上下文的命中元数据和筛选统计。
5. 对新流程关闭病程公共部分提取。
6. 完成单元测试、集成测试和 `RULE-056` 全链路 A/B。
