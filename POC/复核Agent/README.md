# 复核 Agent

本 Agent 读取查询程序生成的 `复核上下文.json`，调用与规则证据 Agent 相同的模型，对事实、申诉命题和整体案件进行复核。

## 模型

默认模型配置与规则证据 Agent 一致：

- `qwen3.6-27b`；
- 关闭思考模式；
- `temperature=0`；
- JSON对象输出。

提示词要求证据和理由使用最小必要内容，以减少输出时间；程序不设置最大输出Token，由模型服务端决定输出上限。

程序优先读取当前目录的 `.env`。如果当前目录没有 `.env`，默认复用 `POC/规则证据Agent/.env`。也可以通过 `--env-file` 指定其他配置。

## 输入输出

默认输入：

```text
D:\AI\AI_S2\POC\查询结果\复核上下文.json
```

默认输出：

```text
D:\AI\AI_S2\POC\复核结果\复核结果.json
```

## 运行

```powershell
cd D:\AI\AI_S2\POC\复核Agent
C:\Users\weyk\anaconda3\python.exe -m review_agent
```

指定复核轮次：

```powershell
C:\Users\weyk\anaconda3\python.exe -m review_agent --review-round 2
```

只校验上下文，不调用模型：

```powershell
C:\Users\weyk\anaconda3\python.exe -m review_agent --dry-run
```

完整参数：

```powershell
C:\Users\weyk\anaconda3\python.exe -m review_agent `
  --context "D:\AI\AI_S2\POC\查询结果\复核上下文.json" `
  --output "D:\AI\AI_S2\POC\复核结果\复核结果.json" `
  --review-round 1
```

## 校验

程序会在写入结果前校验：

- 所有事实和命题是否完整输出；
- 病历引用是否确实存在于对应 `recordContent`；
- 结构化字段引用是否与查询结果一致；
- 上游提供的命题表达式是否合法；
- 表达式是否覆盖全部命题；
- `overall_logic_status`是否与程序计算结果一致；
- 复核状态、案件状态和最终结论是否一致。

程序不会写死P01、P02、P03之间的关系。规则证据Agent提供逻辑表达式，复核模型仅接收，不生成或修改，程序只负责解析和计算。

每次执行完成后，命令行会显示从发起模型调用到模型结果校验完成的整体输出时间。
如果模型接口支持流式响应，还会显示模型调用的首Token耗时、Token/s、调用用时、输入Token、输出Token和总Token；接口未返回Token用量时，相关Token数会使用估算值。每个来源阶段执行一次完整复核调用；仅当证据引用经过程序自动纠正后仍无法验证时，该阶段额外执行一次小型引用专项修复。专项修复仍失败时，程序将受影响事实安全降级为`UNKNOWN`并继续输出结果，不会因引用错误中断。`overall_logic_status`由程序根据`expression`和`proposition_reviews`确定性计算并写入，不采用模型自行填写的值。

带有 `source_staging=true` 的新上下文先仅提供各事实的主要来源及对应共享证据池，校验也仅使用该阶段可见的证据。第一阶段最终合规时停止；违规、未知或冲突且存在次要来源时，第二阶段提供主次全部证据独立重新复核，不携带第一阶段判断，命题表达式保持不变。只有最后使用的阶段结果落盘，第二阶段接口失败不会把第一阶段违规当作最终结果写入。无次要来源时不重复调用。旧版没有级别信息的上下文继续按原方式一次提供全部证据，命令行明确提示重新运行查询程序可启用分阶段流程。来源级别不等于证据证明力；按本策略第一阶段合规即停止，不检查尚未提供的次要来源反证。

为减少模型输出Token，主复核调用只要求模型返回事实编号、事实判断、证据、理由、命题判断、复核状态和最终理由。案件标识、事实元数据、整体逻辑状态、案件状态及完整最终结论由程序恢复后再执行原有校验，判断校验规则保持不变。

新生成的复核上下文及复核结果不再包含 `一级证据域`、`二级证据标签`，使用唯一 `fact_id` 关联事实及原始证据。`target_fact`、`necessity`、查询状态、原始数据和上游 `logical_expression` 保持不变；规则证据及查询取证阶段仍使用标签。旧版带标签且没有 `fact_id` 的上下文仍可读取，程序按原事实顺序分配编号，但不会把标签恢复到新复核结果中。已有上下文和结果文件不会自动改写，需重新执行对应生成命令。

诊断判断遵循以下边界：与本次就诊和适用时间一致的病历原文明确记载目标疾病或临床等义诊断时，可直接支持该疾病；结构化诊断列表缺少同名记录只能表示该列表记录不完整。原始规则未明确要求主要病因、唯一病因或排除共存疾病时，不得新增这些条件；共存的带状疱疹等诊断不能单独否定病历中已明确记载的目标诊断。

同一事实下来源和字段一致的多条结构化引用，模型可用一条证据的 `quotes` 非空字符串数组合并输出；单值仍使用 `quote`，两者不能同时填写。程序在主复核及引用专项修复中检查数组格式并逐条展开，每个值仍必须通过原始来源和字段校验。全部校验通过后，程序将同一事实下同来源同字段的多值引用合并为 `quotes` 数组并保存，即使模型返回多条 `quote` 也会合并。结果校验兼容单值和合并格式；冲突证据数量按展开后的引用计算。不同事实、不同来源、不同字段及病历引用不合并；事实状态、命题状态和上游命题关系的处理不变。
